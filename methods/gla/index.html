    Gated linear attention¶

    A data-dependent diagonal gate on the recurrent state.

    key
    gla · ab.build("gla")
    category
    recurrent
    objective
    modify — defines a different operator; fidelity to softmax is not the goal
    class
    attnbank.GatedLinearAttention · attnbank/methods/recurrent/gla.py
    monograph
    sec:memory-state

    What it changes¶

    Every category in the bank changes one object in the reference operator \(y(q)=\int v\,\mathrm{d}\pi_q\); this method changes the operator. \(y\) is produced by a finite-state recurrence over positions rather than by an integral against a measure — though it is still linear in \(v\), which is why the weights can be recovered at all.

    It pursues modification: it defines a different operator. Asking how closely it approximates softmax is asking the wrong question — it is not trying to.

    What it declares¶

    Each row is a commitment the conformance suite tests, not a description.

    attribute declared what that commits it to
    supports_causal yes causal=True masks so query \(i\) sees keys \(0 \dots i + (n-m)\).
    expresses_weights yes it can name \(\widehat\pi_q\) on the original \(n\) positions, so it enters the error decomposition.
    row_stochastic no the weights are not a probability measure — signed, or not summing to one — so the output can leave the convex hull of the values.
    head_independent yes each head is computed from its own \(K, V\).
    trainable no no learned parameters — what you build is what the paper describes.

    Correctness anchor¶

    None, and that is the declaration. objective = modify means this is a different operator, not an approximation of softmax, so neither anchor applies. The conformance suite does not skip the check — it asserts the exemption, requiring limit_config() and convergence_configs() to both be None for a modify method.

    Cost model¶

    Analytic, per (batch, head). At \(m = 1024\), \(n = 1024\), \(d = 64\), \(dv = 64\) and bytes_per_el=2, against the reference operator at the same shape:

    quantity this method softmax ratio
    flops 16,973,824 268,435,456 0.0632×
    state_bytes 8,192 262,144 0.0312×
    bytes_moved 524,288 4,718,592 0.111×

    Counted operations and resident bytes, not measured time — a cost model is not a benchmark. These are what the monograph's capacity arguments are made of; examples/08_cost_and_capacity.py walks the comparison through properly.

    The numbers are the method's own cost(), evaluated — the declaration, not a measurement:

    def cost(self, m, n, d, dv, bytes_per_el=2):
    r = self.state_rank or d
    return recurrent_cost(m, n, r, dv, bytes_per_el, gate_flops=3)

    Backends¶

    reference only, and that is the correct answer. A scan over positions with a fixed-size state is a different program from a masked softmax.

    reference is plain PyTorch — the correctness anchor and the default. Declaring a second backend is a claim that it equals the first, checked by tests/test_conformance.py::test_backend_equivalence; declaring sdpa here would be pretending. See Backends.

    Diagnostics returned in extras: gate, log_gate, mass, state_rank.

    Configuration¶

    parameter default
    gate_temp 16.0
    gate_bias 0.0
    normalize False
    state_rank None

    gate_temp is the paper's tau in alpha = sigmoid(.)^{1/tau}.

    gate_bias shifts the gate logits (positive = remember longer). state_rank truncates the key/query dimension and so is the size of the recurrent state, state_rank x d_v; None keeps all d channels.

    ab.describe("gla") returns the same keys alongside everything else this page states.

    Run it¶

    import torch, attnbank as ab

torch.manual_seed(0)
b, h, n, d = 1, 2, 64, 32
q, k, v = (torch.randn(b, h, n, d) for _ in range(3))

attn = ab.build("gla", gate_temp=16.0, gate_bias=0.0)
out = attn(q, k, v, causal=True,
           return_weights=True)

print(attn)
print(out)
print("invariant W:", out.check_invariant(v))

# objective = modify: this is a different operator and fidelity to softmax
# is not its goal, so there is no error to quote. What it *is* doing shows
# up in its own diagnostics.
print("row_stochastic =", attn.row_stochastic, "| first row sums:",
      [round(x, 4) for x in out.weights.sum(-1)[0, 0, :4].tolist()])
print("extras:", sorted(out.extras))

    In the paper's notation¶

    monograph sec:memory-state, tab:memory-recurrences (row "GLA / Mamba-2")

    The operator is

    S_t = Diag(alpha_t) S_{t-1} + k_t v_t^T,      y_hat_t = S_t^T q_t,
alpha_t = sigmoid(W_alpha x_t)^{1 / tau} in (0, 1)^r,     tau = 16,

    the first method in the family whose transition A_t = Diag(alpha_t) depends on the input. Retention can only trade recency against nothing — one rate, chosen in advance, applied to every channel and every token. A data-dependent diagonal gate lets the operator decide per token and per channel what to keep, which is how a fixed r x d_v state stops being a pure recency window and starts being selective. This is the same mechanism Mamba-2's SSD writes as a scalar a_t; GLA keeps it diagonal.

    What it does not do is restore the contract. y_hat_t = S_t^T q_t has no denominator — the GroupNorm in the GLA block is not one — and q, k are raw projections with no positive feature map, so the weights

    w_{tj} = < q_t , (prod_{u = j+1}^{t} alpha_u) * k_j > / sqrt(d),    j <= t,

    are signed and their row sums are whatever the gates and the content make them. That is three of the properties of eq:attention_expectation gone at once (sec:memory-state): normalization invariance, constant preservation and convex-hull confinement. normalize=True restores a measure and is not GLA.

    The gate. A trained GLA computes alpha_t from a low-rank projection of the token; with no training there is no W_alpha, so this reference reads the gate off the key itself, alpha_t = sigmoid(k_t)^{1 / tau}. It is a stand-in for the learned map and is stated here rather than hidden: what the library needs from it is that the gate be in (0, 1), data-dependent, and per channel, and all three survive. The 1 / tau exponent is the paper's, and it is load-bearing — it keeps log alpha = logsigmoid(k) / tau close to zero, which is what stops the cumulative product from underflowing over a long prefix. gate_temp=1 turns it off and the state's memory collapses to a few tokens.

    The cumulative products are taken in log space by _gated.gated_weights, which is the numerically stable half of the chunked GLA kernel; see that module.
