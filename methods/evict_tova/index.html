    TOVA¶

    Drop the token the current query cares least about, one per step.

    key
    evict_tova · ab.build("evict_tova")
    category
    compress
    objective
    approximate — targets fidelity to dense softmax; judged by output error

    What it changes¶

    Every category in the bank changes one object in the reference operator \(y(q)=\int v\,\mathrm{d}\pi_q\); this method changes the stored context \((\mu, k, v)\) itself. This is the one category that routinely perturbs the integrand, so \(\widehat v \neq v\) and the error has a value term.

    It pursues approximation: it is trying to be dense softmax, so it is fair to judge it by output error, and it must supply a correctness anchor saying where it becomes exact.

    What it declares¶

    Each row is a commitment the conformance suite tests, not a description.

    attribute declared what that commits it to
    supports_causal yes causal=True masks so query \(i\) sees keys \(0 \dots i + (n-m)\).
    expresses_weights yes it can name \(\widehat\pi_q\) on the original \(n\) positions, so it enters the error decomposition.
    row_stochastic yes those weights are \(\ge 0\) and sum to one: \(\widehat\pi_q\) is a probability measure.
    head_independent yes each head is computed from its own \(K, V\).
    trainable no no learned parameters — what you build is what the paper describes.

    Correctness anchor¶

    Exact limit. Built with budget=None this method provably is dense softmax, and tests/test_conformance.py asserts it — output and weights, float32 and float64.

    >>> ab.describe("evict_tova").limit_config
{'budget': None}

    Cost model¶

    Analytic, per (batch, head). At \(m = 1024\), \(n = 1024\), \(d = 64\), \(dv = 64\) and bytes_per_el=2, against the reference operator at the same shape:

    quantity this method softmax ratio
    flops 2,105,344 268,435,456 0.00784×
    state_bytes 2,048 262,144 0.00781×
    bytes_moved 2,359,296 4,718,592 0.5×

    Counted operations and resident bytes, not measured time — a cost model is not a benchmark. These are what the monograph's capacity arguments are made of; examples/08_cost_and_capacity.py walks the comparison through properly.

    The numbers are the method's own cost(), evaluated — the declaration, not a measurement:

    def cost(self, m, n, d, dv, bytes_per_el=2):
    b = max(1, min(self.budget or n, n))
    return {"flops": 2 * m * b * (d + dv) + m * b,
            "state_bytes": b * (d + dv) * bytes_per_el,
            "bytes_moved": (m * d + m * b * (d + dv) + m * dv) * bytes_per_el}

    Backends¶

    reference only, and that is the correct answer. It reports the omitted mass eps (and the \(\chi^2\) divergence of the renormalisation) in extras, which needs the full score matrix. A kernel that avoids materialising that matrix is a kernel that cannot produce them.

    reference is plain PyTorch — the correctness anchor and the default. Declaring a second backend is a claim that it equals the first, checked by tests/test_conformance.py::test_backend_equivalence; declaring sdpa here would be pretending. See Backends.

    Diagnostics returned in extras: budget, chi2, eps, evicted_at, k_realized, support.

    Configuration¶

    parameter default
    budget 8

    budget: the multi-state size, i.e. how many (k, v) pairs survive.

    ab.describe("evict_tova") returns the same keys alongside everything else this page states.

    Run it¶

    import torch, attnbank as ab

torch.manual_seed(0)
b, h, n, d = 1, 2, 64, 32
q, k, v = (torch.randn(b, h, n, d) for _ in range(3))

attn = ab.build("evict_tova", budget=8)
out = attn(q, k, v, causal=True,
           return_weights=True)

print(attn)
print(out)
print("invariant W:", out.check_invariant(v))

# objective = approximate: it targets dense softmax, so it is judged by
# output error -- split into the distributional and value terms.
row = ab.compare(["evict_tova"], q, k, v, causal=True,
                 configs={"evict_tova": {'budget': 8}})[0]
print({key: round(row[key], 5) for key in
       ("output_error", "distributional_error", "value_error", "tv")})

    In the paper's notation¶

    monograph sec:compress-evict, prop:compress-noeviction

    Reading a decoder as a multi-state RNN, the KV cache is the state and a cache policy is a rule for keeping it bounded. TOVA is the simplest non-trivial such rule: at every step the new token is admitted, and if the cache is over budget the state with the smallest weight under the query that just arrived is deleted. No accumulation over history (that is evict_h2o), no protected recent window (that is sink_window), no observation window (that is evict_snapkv): one query decides, once, and the decision is permanent.

    S_0 = {0},   S_t = topkeep_{b}( S_{t-1} u {t}; pi_{q_t} ),   S_t \ {t} subset S_{t-1}

    Semantics: eviction, and the file is built so that this is visible. The supports are produced by a loop over queries in order, so the set serving query t was fixed by queries <= t and nothing later can restore what they threw away. Two consequences are tested in tests/test_compress_evict.py rather than asserted here:

    • the supports are nested — S_{t+1} subset S_t u {t+1}. window and sink_window are nested too, which is exactly why they are listed in both restrict/ and sec:compress-evict; the content-dependent selectors are not, because a restriction recomputes its set per query and is free to come back to a position it ignored a step ago. topk at the same budget is the comparison;
    • at equal budget the error against dense softmax is larger than topk's, and the gap grows along the query axis: early queries are served by a cache that still holds almost everything, late ones by a cache pruned long before their question was asked. That gap is the whole content of prop:compress-noeviction — restriction hides context, eviction destroys it.

    The current position is the one protection the policy keeps, so that no row is ever left with an empty support (DESIGN.md Sec. 4, rule 10); TOVA keeps it in practice anyway, since a token's own key usually dominates its row. extras['evicted_at'] records the step at which each position was deleted, or -1 if it survived, which is the permanence made inspectable.

    In non-causal mode the whole context is admitted at the first step and the same evict-per-query loop runs over the queries in order: "a streaming cache served by a fixed context", the convention evict_h2o also uses.

    Exact limit: budget = None (nothing is ever evicted).
