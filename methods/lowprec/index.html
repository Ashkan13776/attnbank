    Low-precision attention¶

    Simulated FP8 / INT8 logits and values.

    key
    lowprec · ab.build("lowprec")
    category
    exact
    objective
    approximate — targets fidelity to dense softmax; judged by output error
    class
    attnbank.LowPrecisionAttention · attnbank/methods/exact/lowprec.py
    monograph
    sec:exact-boundary

    What it changes¶

    Every category in the bank changes one object in the reference operator \(y(q)=\int v\,\mathrm{d}\pi_q\); this method changes nothing in \(y(q)=\int v\,\mathrm{d}\pi_q\). The integrand, the measure and the normaliser are the reference operator's; only the order of arithmetic changes.

    It pursues approximation: it is trying to be dense softmax, so it is fair to judge it by output error, and it must supply a correctness anchor saying where it becomes exact.

    What it declares¶

    Each row is a commitment the conformance suite tests, not a description.

    attribute declared what that commits it to
    supports_causal yes causal=True masks so query \(i\) sees keys \(0 \dots i + (n-m)\).
    expresses_weights yes it can name \(\widehat\pi_q\) on the original \(n\) positions, so it enters the error decomposition.
    row_stochastic yes those weights are \(\ge 0\) and sum to one: \(\widehat\pi_q\) is a probability measure.
    head_independent yes each head is computed from its own \(K, V\).
    trainable no no learned parameters — what you build is what the paper describes.

    Correctness anchor¶

    Exact limit. Built with bits=None, fmt=None, bits_p=None this method provably is dense softmax, and tests/test_conformance.py asserts it — output and weights, float32 and float64.

    >>> ab.describe("lowprec").limit_config
{'bits': None, 'fmt': None, 'bits_p': None}

    Cost model¶

    Analytic, per (batch, head). At \(m = 1024\), \(n = 1024\), \(d = 64\), \(dv = 64\) and bytes_per_el=2, against the reference operator at the same shape:

    quantity this method softmax ratio
    flops 268,435,456 268,435,456 1×
    state_bytes 131,072 262,144 0.5×
    bytes_moved 262,144 4,718,592 0.0556×

    Counted operations and resident bytes, not measured time — a cost model is not a benchmark. These are what the monograph's capacity arguments are made of; examples/08_cost_and_capacity.py walks the comparison through properly.

    The numbers are the method's own cost(), evaluated — the declaration, not a measurement:

    def cost(self, m, n, d, dv, bytes_per_el=2):
    b = bytes_per_el if self.bits is None and self.fmt is None else \
        max(1, (8 if self.fmt else self.bits) // 8)
    return {"flops": 2 * m * n * (d + dv), "state_bytes": n * (d + dv) * b,
            "bytes_moved": (m * d + n * (d + dv) + m * dv) * b}

    Backends¶

    reference only, and that is the correct answer. The method exists to expose the intermediate states of the evaluation, which a single fused call does not hand back.

    reference is plain PyTorch — the correctness anchor and the default. Declaring a second backend is a claim that it equals the first, checked by tests/test_conformance.py::test_backend_equivalence; declaring sdpa here would be pretending. See Backends.

    Diagnostics returned in extras: delta_v, s_hat.

    Configuration¶

    parameter default
    bits 8
    fmt None
    bits_p None
    hadamard_qk False
    smooth_k False
    seed 0

    bits: INT width for q, k, v (None = no quantization, the exact limit). fmt: 'e4m3' / 'e5m2' to use FP8 instead of INT. bits_p: optional INT width for the attention weights themselves.

    ab.describe("lowprec") returns the same keys alongside everything else this page states.

    Run it¶

    import torch, attnbank as ab

torch.manual_seed(0)
b, h, n, d = 1, 2, 64, 32
q, k, v = (torch.randn(b, h, n, d) for _ in range(3))

attn = ab.build("lowprec", bits=8, hadamard_qk=False)
out = attn(q, k, v, causal=True,
           return_weights=True)

print(attn)
print(out)
print("invariant W:", out.check_invariant(v))

# objective = approximate: it targets dense softmax, so it is judged by
# output error -- split into the distributional and value terms.
row = ab.compare(["lowprec"], q, k, v, causal=True,
                 configs={"lowprec": {'bits': 8, 'hadamard_qk': False}})[0]
print({key: round(row[key], 5) for key in
       ("output_error", "distributional_error", "value_error", "tv")})

    In the paper's notation¶

    monograph sec:exact-boundary

    This is the method that marks where exactness ends. An FP8/INT8 kernel keeps the evaluation order of prop:exact-monoid but stores the operands at a precision u' >> u, so it satisfies the first clause of def:exact-scheme and fails the second. By the criterion of "which object is changed" it belongs with context compression: quantizing q, k replaces g by g_hat (a distributional error) and quantizing v or P replaces v by v_hat (a value-representation error). Its objective is therefore approximate, not accelerate, which is the whole point of putting it in exact/.

    Simulation is quantize–dequantize in the kernel, per attention head and per tensor:

    Q_b(x) = clamp(round(x / Delta), -2^{b-1}, 2^{b-1} - 1) * Delta,  Delta = max|x| / (2^{b-1} - 1)

    for signed INT-b, and round-to-nearest on the FP8 E4M3 / E5M2 grids. Optional incoherent processing (hadamard=True) multiplies q and k by a shared random orthogonal Hadamard matrix before quantizing, which is exact in infinite precision (<Rq, Rk> = <q, k>) and spreads outlier coordinates, as in FlashAttention-3's FP8 path. Optional smoothing (smooth_k=True) subtracts the token mean of k, which shifts every logit of a query by one constant and so leaves pi_q exactly invariant (SageAttention).

    The quantizers themselves live in attnbank.components.quantization, shared with quantkv: one implementation, one place where the rounding rule is argued about.
