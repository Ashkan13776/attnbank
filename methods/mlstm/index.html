    mLSTM (xLSTM)¶

    mlstm · ab.build("mlstm")

    MLSTM (xLSTM): exponential gating, a matrix memory, and a normaliser state.

    category
    recurrent — one of the seven objects in \(y(q)=\int v\,\mathrm{d}\pi_q\) a method can change
    objective
    modify — defines a different operator; fidelity to softmax is not the goal
    class
    attnbank.MLSTMAttention, attnbank/methods/recurrent/mlstm.py
    monograph
    sec:memory-state

    What it changes¶

    Changes the operator. \(y\) is produced by a finite-state recurrence over positions rather than by an integral against a measure — though it is still linear in \(v\), which is why the weights can be recovered at all.

    It pursues modification: it defines a different operator. Asking how closely it approximates softmax is asking the wrong question — it is not trying to.

    In the paper's notation¶

    sec:memory-state, tab:memory-recurrences. The mLSTM is the one member of this family that keeps a denominator, and keeping it is the whole reason it is here:

    C_t = f_t C_{t-1} + i_t v_t k_t^T,            C_t in R^{d_v x r}   (matrix memory)
n_t = f_t n_{t-1} + i_t k_t,                  n_t in R^r           (normaliser)
y_hat_t = C_t q_t / max(|n_t^T q_t|, 1),

    with i_t = exp(i~_t) an exponential input gate and f_t = sigmoid(f~_t) a scalar forget gate — so A_t = f_t Id, data-dependent but not diagonal: one rate for the whole head, unlike GLA. The interest is entirely in the second and third lines. n_t is the same recurrence driven by k_t instead of k_t v_t^T, so n_t^T q_t is exactly the row sum of the unnormalised weights: the mLSTM carries the denominator of eq:attention_expectation as part of its state, which linear attention threw away and which linear_rnn does not have.

    It still does not get the contract back, and the max(., 1) is why. Dividing by max(|n_t^T q_t|, 1) makes the readout bounded — that was the goal, since an exponential input gate can make the true denominator astronomically small — but it is not division by the mass. When the mass exceeds one the operator is normalised and the row sums to one; when it does not, the row is left alone and sums to less. Row sums are therefore in [0, 1] and the weights are signed (q_t . k_t is a raw inner product), so normalization invariance and constant preservation fail exactly in the small-mass regime, which is reported in extras["clipped"]. That partial restoration is a sharper illustration of sec:memory-state than dropping the normaliser outright: the denominator is present and the invariant still breaks.

    Exponential gating needs the paper's stabiliser or it overflows at the first large logit. With c = cumsum(log f),

    m_t = max_{j <= t} ( log i_j + c_t - c_j ) = c_t + cummax( log i - c )_t,

    and every stabilised coefficient a_{tj} = exp(log i_j + c_t - c_j - m_t) lies in (0, 1] by construction. The denominator floor becomes exp(-m_t) in the same units. This is the recurrence m_t = max(log f_t + m_{t-1}, log i_t) of the paper, written as the prefix scan it is.

    The gates. A trained mLSTM reads i~_t and f~_t off x_t through learned projections. With no training this reference takes two fixed orthogonal directions of the key — the mean <k_t, 1>/sqrt(d) for forgetting and the alternating-sign direction <k_t, (-1)^c>/sqrt(d) for writing — plus the biases below. They are stand-ins, stated rather than hidden; what matters downstream is that both gates are scalar per head and functions of the token, and both are.

    What it declares¶

    Each row is a commitment the conformance suite tests, not a description.

    attribute declared what that commits it to
    supports_causal yes causal=True masks so query \(i\) sees keys \(0 \dots i + (n-m)\).
    expresses_weights yes it can name \(\widehat\pi_q\) on the original \(n\) positions, so it enters the error decomposition.
    row_stochastic no the weights are not a probability measure — signed, or not summing to one — so the output can leave the convex hull of the values.
    head_independent yes each head is computed from its own \(K, V\).
    trainable no no learned parameters — what you build is what the paper describes.

    Configuration¶

    parameter default
    forget_bias 3.0
    input_bias 0.0
    state_rank None

    forget_bias shifts f~ (positive = remember longer, the LSTM default).

    input_bias shifts i~. state_rank truncates the key/query dimension and so is the size of the matrix memory, state_rank x d_v plus the state_rank of the normaliser; None keeps all d channels.

    ab.describe("mlstm")     # the same keys, with everything else it declares

    Correctness anchor¶

    None, and that is the declaration. objective = modify means this is a different operator, not an approximation of softmax, so neither anchor applies. The conformance suite does not skip the check — it asserts the exemption, requiring limit_config() and convergence_configs() to both be None for a modify method.

    Backends¶

    backend what it is
    reference plain PyTorch; the correctness anchor and the default

    reference only, and that is the correct answer. A scan over positions with a fixed-size state is a different program from a masked softmax.

    Declaring a backend is a claim that it equals the reference, checked by tests/test_conformance.py::test_backend_equivalence; declaring sdpa here would be pretending. See Backends.

    Diagnostics returned in extras: clipped, forget_gate, input_gate, mass, stabilizer, state_rank.

    Cost model¶

    Analytic, per (batch, head), declared by the method itself:

    def cost(self, m, n, d, dv, bytes_per_el=2):
    r = self.state_rank or d
    c = recurrent_cost(m, n, r, dv, bytes_per_el, gate_flops=4)
    c["state_bytes"] += r * bytes_per_el         # the normaliser state n_t
    c["flops"] += 2 * n * r + 2 * m * r          # and its update and readout
    return c

    At \(m = 1024\), \(n = 1024\), \(d = 64\), \(dv = 64\) and bytes_per_el=2, against the reference operator at the same shape:

    quantity this method softmax ratio
    flops 17,301,504 268,435,456 0.0645×
    state_bytes 8,320 262,144 0.0317×
    bytes_moved 524,288 4,718,592 0.111×

    A cost model is not a benchmark

    These are counted operations and resident bytes, not measured time. They are what the monograph's capacity arguments are made of; examples/08_cost_and_capacity.py walks through the comparison properly.

    Run it¶

    import torch, attnbank as ab

torch.manual_seed(0)
b, h, n, d = 1, 2, 64, 32
q, k, v = (torch.randn(b, h, n, d) for _ in range(3))

attn = ab.build("mlstm", forget_bias=3.0, input_bias=0.0)
out = attn(q, k, v, causal=True,
           return_weights=True)

print(attn)
print(out)
print("invariant W:", out.check_invariant(v))

# objective = modify: this is a different operator and fidelity to softmax
# is not its goal, so there is no error to quote. What it *is* doing shows
# up in its own diagnostics.
print("row_stochastic =", attn.row_stochastic, "| first row sums:",
      [round(x, 4) for x in out.weights.sum(-1)[0, 0, :4].tolist()])
print("extras:", sorted(out.extras))
