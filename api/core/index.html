    Core types¶

    core ¶

    Core interface for attnbank.

    Every efficient-attention method is an AttentionMethod. The interface mirrors the paper's framework: attention is y(q) = E_{x ~ pi_q}[v(x)], and a method may change the evaluation (exact), the interaction g, the accessible support, the context representation (mu, k, v), the factorization of pi_q, or the operator.

    Tensor convention (all methods): query [B, H, m, d], key [B, H, n, d], value [B, H, n, dv]. Causal masking aligns the last query with the last key (decode-friendly), so m <= n and query i sees keys 0 .. i + (n - m).

    The public argument names are query, key, value -- the transformers convention, which also frees k to mean a method's own budget (ab.attend("topk", q, k, v, k=64)). They remain positional, so attn(q, k, v) is unchanged, and the short spellings q=, k=, v= are still accepted as keywords for tensors.

            return_weights: bool = False) -> AttentionOutput:
    """Run the method.

    Parameters
    ----------
    query:
        ``[B, H, m, d]``. Also accepted positionally as ``q``.

        ``O(m n)`` memory, so it is off by default; the conformance suite and
        :func:`attnbank.compare` turn it on.

                        return_weights=return_weights)

    def check_qkv(query: Tensor, key: Tensor, value: Tensor,
              where: str = "") -> None:
    """Validate the ``[B, H, n, d]`` convention, naming the argument that is wrong.

    Raises :class:`~attnbank.errors.ShapeError` with the offending argument, what was
    expected and what arrived -- never a bare broadcasting failure from deep inside a
    method.

    Examples
    --------
    >>> import torch
    >>> from attnbank.core import check_qkv
    >>> check_qkv(torch.randn(1, 2, 4, 8), torch.randn(1, 2, 6, 8), torch.randn(1, 2, 6, 3))
    >>> check_qkv(torch.randn(4, 8), torch.randn(1, 2, 6, 8), torch.randn(1, 2, 6, 3))
    Traceback (most recent call last):
        ...
    attnbank.errors.ShapeError: query must be [B, H, m, d]; got [4, 8] (2 dims, expected 4)
    """
    suffix = f" (in {where})" if where else ""
    for arg, t, spec in (("query", query, "[B, H, m, d]"), ("key", key, "[B, H, n, d]"),
                         ("value", value, "[B, H, n, dv]")):
        if not isinstance(t, Tensor):
            raise ShapeError(f"{arg} must be a torch.Tensor{suffix}; got "
                             f"{type(t).__name__}. Tensors are {spec}.")
        if t.dim() != 4:
            raise ShapeError(shape_message(arg + suffix, spec, t.shape,
                                           f"{t.dim()} dims, expected 4"))
    if query.shape[:2] != key.shape[:2] or query.shape[:2] != value.shape[:2]:
        raise ShapeError(
            f"query, key and value must share the leading [B, H]{suffix}; got "
            f"query{list(query.shape[:2])}, key{list(key.shape[:2])}, "
            f"value{list(value.shape[:2])}")
    if key.shape[-2] != value.shape[-2]:
        raise ShapeError(
            shape_message("value" + suffix, f"[B, H, n, dv] with n = {key.shape[-2]} "
                          "(the number of keys)", value.shape,
                          f"n = {value.shape[-2]} values for {key.shape[-2]} keys"))
    if query.shape[-1] != key.shape[-1]:
        raise ShapeError(
            shape_message("key" + suffix, f"[B, H, n, d] with d = {query.shape[-1]} "
                          "(the query head dimension)", key.shape,
                          f"d = {key.shape[-1]}"))
    if query.shape[-2] > key.shape[-2]:
        raise ShapeError(
            f"m = {query.shape[-2]} queries for n = {key.shape[-2]} keys{suffix}. "
            "Causal masking aligns the LAST query with the LAST key, so m <= n is "
            "required; pass the full key/value context alongside the query block.")

    def causal_mask(m: int, n: int, device=None) -> Tensor:
    """Boolean ``[m, n]`` mask, ``True`` where key ``j`` is visible to query ``i``.

    Queries are aligned with the **last** keys, so query ``i`` sees ``0 .. i + (n - m)``.
    The same code path therefore serves prefill (``m == n``) and decode (``m < n``).

    Examples
    --------
    >>> from attnbank import causal_mask
    >>> causal_mask(2, 3).int()
    tensor([[1, 1, 0],
            [1, 1, 1]], dtype=torch.int32)
    """
    i = torch.arange(m, device=device)[:, None] + (n - m)
    j = torch.arange(n, device=device)[None, :]
    return j <= i

    def scores(q: Tensor, k: Tensor, scale: float, causal: bool) -> Tensor:
    """Scaled logits ``s = beta <q, k_j>``, ``-inf`` on masked entries, ``[..., m, n]``.

    Examples
    --------
    >>> import torch
    >>> from attnbank import scores
    >>> q, k = torch.ones(1, 1, 2, 4), torch.ones(1, 1, 3, 4)
    >>> scores(q, k, scale=0.5, causal=True)[0, 0]
    tensor([[2., 2., -inf],
            [2., 2., 2.]])
    """
    s = torch.einsum("...md,...nd->...mn", q, k) * scale
    if causal:
        mask = causal_mask(q.shape[-2], k.shape[-2], device=q.device)
        s = s.masked_fill(~mask, float("-inf"))
    return s

    def masked_softmax(s: Tensor, support: Optional[Tensor] = None) -> Tensor:
    """Softmax of ``s`` restricted to ``support``, computed in log space.

    ``support`` is a boolean tensor broadcastable to ``s``. Rows with empty support
    return the uniform distribution over the row rather than ``nan`` (documented
    fallback of DESIGN.md Sec. 4, rule 10); such rows are reported by the caller.

    Examples
    --------
    >>> import torch
    >>> from attnbank import masked_softmax
    >>> s = torch.tensor([[0.0, 0.0, 0.0]])
    >>> masked_softmax(s, support=torch.tensor([[True, True, False]]))
    tensor([[0.5000, 0.5000, 0.0000]])
    >>> masked_softmax(s, support=torch.tensor([[False, False, False]]))  # no nan
    tensor([[0.3333, 0.3333, 0.3333]])
    """
    if support is not None:
        s = s.masked_fill(~support, float("-inf"))
    dead = torch.isneginf(s).all(dim=-1, keepdim=True)
    s = torch.where(dead, torch.zeros_like(s), s)
    return torch.softmax(s, dim=-1)

    online_softmax ¶

    The online-softmax monoid of prop:exact-monoid (sec:exact-tiling).

    For a block J of key indices the partial state is

    sigma_J = (a_J, l_J, u_J),
a_J = max_{j in J} s_j,
l_J = sum_{j in J} e^{s_j - a_J},
u_J = sum_{j in J} e^{s_j - a_J} v_j,

    with merge (eq:exact-merge)

    (a1,l1,u1) + (a2,l2,u2) = (a, e^{a1-a} l1 + e^{a2-a} l2, e^{a1-a} u1 + e^{a2-a} u2),
a = max(a1, a2),

    readout rd(a,l,u) = u/l and identity (-inf, 0, 0). (Sigma, +, 0) is a commutative monoid, so the fold over any partition, in any bracketing, gives y(q).

    flash folds left-to-right over key blocks in one pass; splitk folds per chunk and merges once (or as a tree). They share this file precisely because the proposition says the two must agree.

    quantization ¶

    Quantise--dequantise, in every flavour the bank needs (sec:exact-boundary, sec:compress-quant).

    Two methods quantise, for different reasons, and they share this file so that the quantiser is one implementation and the claim about it is one test.

    • lowprec quantises q, k, v (and optionally P) inside the kernel: the evaluation order of prop:exact-monoid is kept, the operand precision is not. That is where exactness stops.
    • quantkv quantises the stored cache: keys and values stay on the same domain, only their representation changes. The key error enters as an exponential tilt of pi_q, the value error linearly and attention-weighted -- the asymmetry of prop:compress-sensitivity.

    Everything here is a quantise--dequantise simulation in the input dtype: the point is the error it introduces, not the storage it would save, and simulating keeps the bank runnable on any device.

    All scales are taken over an axis that makes the quantiser causal and head-independent unless the caller explicitly asks otherwise (axis='channel' pools statistics across tokens, which quantkv refuses under causal=True).

    def affine_quantize(x, bits, axis="token", group=None):
    """Uniform asymmetric quantize--dequantize of ``x`` ``[..., t, c]``.

    ``Q_b(x) = round((x - lo) / Delta) * Delta + lo`` with ``Delta = (hi - lo) / (2^b - 1)``
    and ``lo, hi`` the min and max over a *group*. ``axis='token'`` shares a scale among
    ``group`` channels of one token (KIVI's value grouping); ``axis='channel'`` shares
    it among ``group`` tokens of one channel (KIVI's key grouping). ``bits=None`` is the
    identity, which is the exact limit of ``quantkv``.

    Examples
    --------
    >>> import torch
    >>> from attnbank.components import affine_quantize
    >>> x = torch.tensor([[[0.0, 0.25, 0.5, 1.0]]])
    >>> affine_quantize(x, bits=1, axis="token")     # 1 bit: two levels, 0 and 1
    tensor([[[0., 0., 0., 1.]]])
    >>> q = affine_quantize(x, bits=3, axis="token")
    >>> torch.allclose(affine_quantize(q, bits=3, axis="token"), q)   # idempotent
    True
    """
    if bits is None:
        return x
    levels = 2 ** bits - 1
    t, c = x.shape[-2], x.shape[-1]
    if axis == "token":
        g = group or c
        pad = (-c) % g
        xx = torch.nn.functional.pad(x, (0, pad)) if pad else x
        blk = xx.unflatten(-1, (xx.shape[-1] // g, g))          # [..., t, ng, g]
        out = _quant_blocks(blk, levels).flatten(-2)
        return out[..., :c]
    if axis == "channel":
        g = group or t
        pad = (-t) % g
        xx = torch.nn.functional.pad(x, (0, 0, 0, pad)) if pad else x
        blk = xx.unflatten(-2, (xx.shape[-2] // g, g))          # [..., ng, g, c]
        blk = blk.transpose(-2, -1)                             # [..., ng, c, g]
        out = _quant_blocks(blk, levels).transpose(-2, -1).flatten(-3, -2)
        return out[..., :t, :]
    raise ValueError(f"axis must be 'token' or 'channel', got {axis!r}")

    def topk_support(score, visible_mask, budget):
    """Boolean support of the ``budget`` largest ``score`` among the visible keys.

    Invisible keys get ``-inf`` so they can never be selected; ``budget = None`` or a
    budget at least as large as the row selects every visible key, which is the exact
    limit of every selector in this package.

    Examples
    --------
    >>> import torch
    >>> from attnbank.components import topk_support
    >>> score = torch.tensor([[0.1, 0.9, 0.5]])
    >>> topk_support(score, torch.ones(1, 3, dtype=torch.bool), 2).int()
    tensor([[0, 1, 1]], dtype=torch.int32)
    """
    n = score.shape[-1]
    if budget is None or budget >= n:
        return visible_mask.clone()
    s = score.masked_fill(~visible_mask, float("-inf"))
    idx = s.topk(budget, dim=-1).indices
    sup = torch.zeros_like(visible_mask).scatter_(-1, idx, True)
    return sup & visible_mask

    sdpa ¶

    The shared sdpa execution path (backend="sdpa").

    torch.nn.functional.scaled_dot_product_attention is the production kernel that ships with PyTorch: on CUDA it dispatches to FlashAttention-2 or to the memory-efficient kernel, on CPU to a fused math path. It computes exactly

    y = softmax(beta <q, k> + mask) v,

    which is the operator of softmax, flash, and -- after their own preprocessing -- gqa and mla. Those four declare the backend; nothing else in the bank does, because nothing else in the bank is a dense softmax over a mask once its extras are accounted for.

    Two details this helper exists to get right.

    Alignment. is_causal=True masks with the diagonal aligned at the top left. The library's convention (DESIGN.md Sec. 2) aligns the last query with the last key, so query i sees 0 .. i + (n - m). Those agree only when m == n. The helper always passes an explicit boolean mask built by attnbank.causal_mask, so decode (m < n) is correct rather than accidentally right.

    Kernel choice. sdpa_kernel= pins the sub-backend -- "flash", "mem_efficient", "math", or None to let torch choose. Pinning matters for a benchmark: "SDPA" is three different kernels with three different performance and numerics profiles. An unavailable sub-backend raises rather than silently choosing another.
